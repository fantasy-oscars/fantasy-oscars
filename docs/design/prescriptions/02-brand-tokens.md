# 02 Brand tokens (seven brands, light and dark)

Package: the token values for every contract slot of all seven brands, plus the shared component rules those values depend on. Built in three chunks: **chunk 4** (step 0 shared rules and refined-gold, then red-carpet and noir), **chunk 5** (ballot, festival), **chunk 6** (technicolor, lightbox). Builder: implement this file, not the mockups. Section 3.5 onwards is organised so each chunk can take its pair alone; sections 3.1–3.4, 4 and 9 are chunk 4 step 0 and are prerequisites for chunks 5 and 6.

Brand letters: A refined-gold, B red-carpet, C ballot, D noir, E festival, F technicolor, G lightbox.

## 1. Scope

**In scope**

1. Every contract slot (`contract.ts`) for all seven brands, light and dark: 15 colours, 3 shadows (overlay is new), type, `fonts`, wordmark, shape, navigation, decorations, `homeLayout`.
2. Three small contract additions that change pixels now: `type.displayWeight`, `type.displayCase` and `shadows.overlay` (3.2).
3. Refined-gold: the owner chooses between adopting the canvas palette (recommended) and filling only the provisional slots (escalation a1). Both value sets are given (3.4).
4. Nominee pill states and focus rings brought in line with the designer's `Pill-States` board where they meet prescription 01's rules (4.1, 4.2). This is required here, not later: once primaries such as laurel (festival) and cherry (technicolor) land, 01's primary-tinted hover and armed states would paint status hues on the board.
5. One skin for floating layers (modals including the phone nominee card, the nav drawer, toasts, menus and dropdowns, tooltips), built on the new overlay shadow (4.5); and the rules for `primary` used outside fills (4.6).
6. Nine marginal improvements (section 9), applied to every brand.
7. The visual matrix gains a brand dimension and a key-screen subset for new brands (6.1).

**Not changed**

- Shared tokens (`shared.ts`): win gold, status colours, danger, podium metals. The canvas pool equals them exactly (3.3). Danger as text is a carried problem; its fix is an owner decision (3.3a, a5).
- Mantine `red` / `green` / `yellow` (toast stripes, error borders) and the Mantine `Skeleton` greys (loading states, not captured): chunk 7, as 01 set out.
- Component rendering of the enum slots (`nav-active`, `button-shape`, `rule-style`, decorations, wordmark two-tone, `home-layout`): values are set here, rendering belongs to chunks 7–11.
- Layout, spacing, draft board geometry (`--fo-db-*`), the countdown pulse mechanics (chunk 9), status chips (chunk 7), home compositions (chunk 10).
- `ENABLED_BRAND_IDS` stays `["refined-gold"]` until chunk 12. New brands are reachable only with `VITE_FO_ENABLE_ALL_BRANDS=1` in non-production builds.

**3.0a Shadow rings.** `shadow-card` is read by `.baseline-card` (landing, account, standard and action cards) which has no border. A flat brand with no shadow would lose the card edge, so its `card` value is a ring in the board's card-border colour and its `raised` (hover) value is a ring in `ruleStrong` or ink. "No shadow" is written `0 0 0 0 transparent`, never `none`: `--fo-shadow-card-focus` and other tokens concatenate the slot into a list, where `none` is invalid.

**3.0b Contrast notation.** Five numbers are against `page / surface / raised / sunken / draft card`. The draft card is `rgba(text, 0.03)` over `page` (`.dr-card`). Text needs 4.5 (3.0 for 24 px+ or 18.66 px bold); non-text indicators need 3.0. `faint` and `rule` are decorative and carry no requirement. Overlay rings are given as three numbers, against `page / raised / sunken`.

**3.0c Card edges where the shadow is transparent (E only).** Festival is the only brand whose `shadow-card` and `shadow-raised` are transparent, so its cards are told apart by fill alone: `raised` on `page` 1.09 in both modes, `sunken` (nested cards, list rows) on `raised` 1.09 light and 1.11 dark. That holds only while a default card never sits on `raised` or `surface`. Checked in the code:

- The three `surface` readers carry no raised child. `.wizard-panel.is-primary` (a `StandardCard` in `CreateNominationPanel`) holds inputs, comboboxes, `.list-row` (sunken with a `rule` border) and text. Its `border-color` rule has no effect because the card has no border, so its edge is `shadow-card` like any card: in E, the 1.09 fill. `.hero` has a `rule` border and no current reader in the screens. `.admin-next-step` has a 3 px primary border and holds a title, text and a button.
- The one card inside a card (`DraftPlansScreen`, plan detail) already uses `tone="nested"`.
- Mantine `Card` and `.card` draw their own `rule` border in every brand.
- Floating layers take the overlay edge (4.5), so a menu over a card is never raised on raised without an edge.

Rule for the builder and later chunks: in E, a card inside a raised or surface container must be `tone="nested"`. A default card there would have no edge at all. The other six brands draw a ring in `shadow-card`, so a raised card keeps an edge wherever it sits.

**3.0d Well step.** `sunken` against `raised` / `page`, light then dark: A option 1 1.16 / 1.09, 1.11 / 1.21; B 1.25 / 1.11, 1.09 / 1.15; C 1.18 / 1.10, 1.08 / 1.17; D 1.21 / 1.10, 1.11 / 1.21; E 1.09 / 1.19, 1.11 / 1.21; F 1.17 / 1.11, 1.16 / 1.27; G 1.27 / 1.08, 1.10 / 1.19. All meet 1.07. Option 2 (today's palette) is 1.05 / 1.13 and 1.00 / 1.22, which is why its hover wells on cards do not show today.

### 3.2 Contract changes

**In this package (chunk 4 step 0).** Three slots, emitted by `css.ts`, read immediately, with a value for every brand and mode: the two type slots in 3.11, the overlay shadow in each brand table (3.4–3.10).

**Risks**

- **R1 Flag in a build.** `orchestration.ts` honours the flag only when `!import.meta.env.PROD`, and `vite build` sets `PROD = true` in every mode, so the visual stack's build ignores the flag today. Fix: gate on `import.meta.env.MODE !== "production"` in orchestration (matching `brandInit.ts`'s `mode === "production"` guard), and build the visual stack with `--mode visual` plus the flag. Keep the unit test that the production `brand-init.js` renders only enabled brands.
- **R2 Preference write-back.** Without the `/auth/me` route override, a signed-in persona copies the local preference to its account and pollutes parallel captures (6.1).
- **R3 Pill specificity.** The armed rule must out-rank the `:where` hover rule and come before the winner rules; keep 01's order (hover → hover-match → armed → winner → combos → focus).
- **R4 Outline clipping.** The pill focus outline reaches 4 px beyond the pill. Board cards have 10 px padding. Check rail panes by keyboard in functional QA; if a pane clips it, give `.dr-railPaneBody` an inline padding of at least 4 px (not captured).
- **R5 Shadow lists.** Use `0 0 0 0 transparent`, never `none` (3.0a).
- **R6 Nav measurement.** New body faces change link widths, so the 500–900 inline-or-drawer decision may flip; not captured. Functional QA checks 768 in each brand.
- **R7 Uppercase titles** (D) in admin and content pages may truncate where a title row is `nowrap`; functional QA scans admin in noir.
- **R8 Variable fonts** must not set `font-variation-settings`; weight comes from `font-weight` only.
- **R9 Overlay specificity.** Mantine's own rules for these layers are single-class, and the Notification background sits under `:where(...)`. The 4.5 rules win by load order only. If a Mantine upgrade reorders the CSS, the grey shadows return; a unit or visual check on `draft-live-armed` catches it.
- **R10 F's offset on overlays.** The 5 px offset below a toast or dropdown can be clipped by a container with `overflow: hidden` (the Combobox dropdown has it on its own box, which is fine; check the notifications container at 390). Functional QA opens a menu, a Select and a toast in technicolor.
