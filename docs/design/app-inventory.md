# App inventory

A map of the web app for people who prescribe and judge visual changes. It was written from the code at `origin/main` after PR #394, corrected after PRs #395-#400 (structural prerequisites, brand token contracts and palettes) and updated after PRs #403 (brand header, nav, wordmark, buttons) and #404 (brand cards, decorations, chips, alerts, countdown cue, `EmptyState`) and the visual baselines in `tests/visual/__screenshots__`. Paths are relative to `apps/web/src` unless they start with `tests/`, `docs/` or `packages/`.

"Today" means the single released brand, `refined-gold` (`theme/brands/refined-gold.ts`); `ENABLED_BRAND_IDS` in `packages/shared/src/brands.ts` is `["refined-gold"]`, so users never see another brand yet (the other six render only in the visual suite and tests). Defined brands: refined-gold, red-carpet, noir, ballot, festival, technicolor and lightbox (all seven in `BRAND_IDS` and `BRAND_DEFINITIONS`). Where something could not be confirmed from code or screenshots it is marked **Unverified**.

### 1.1 Home (`/`) in depth

Glue: `app/pages/HomePage.tsx` calls `useLandingOrchestration({ seasonsEnabled: Boolean(user) })` (`orchestration/landing/orchestration.ts`) and renders `features/home/screens/LandingScreen.tsx` inside `ShellLayout` (header, nav, banners, footer; the shell constrains width and applies gutters). `LandingLayout` (`primitives/layouts/LandingLayout.tsx`) is a three-region grid (`hero`, `updates`, `aside`); the screen builds each as a node. Decisions: `decisions/landing.ts` (status label, tagline, ceremony label, `titleCase`, `computeHeroTitleTier`, `formatUpdateDate`), `decisions/landing/seasonPreviews.ts`, `decisions/statusTone.ts`.

**Layout slots.** Three grid areas, `hero`, `updates`, `aside`, placed by `--brand-home-areas` (`primitives/baseline.css` 1-70). Columns `minmax(0, 1.6fr) minmax(0, 1fr)`. Column placement: hero over the left column (`"hero aside" "updates aside"`). Masthead placement: hero spans both columns (`"hero hero" "updates aside"`). DOM and focus order are fixed for every brand: hero, updates, aside (create-league card, "Active seasons" heading and list). At 500 px and below the grid is one column in that order.

#### Hero surface

The hero is a flat surface that does not invert with the colour scheme. `.baseline-heroCard` reads `--brand-home-hero-bg`, `-fg`, `-fg-rgb`, `-muted`, `-radius`, `-rule`, `-align` and `-panel` (0 or 1, which multiplies its padding): `darkPanel` paints `--brand-dark-surface` with `--brand-dark-text` in both modes, `accentPanel` paints `--brand-light-accent` with `--brand-light-page` text (muted at 90 % alpha) in both modes, and `open` is transparent type on the page with a 2 px (3 px double where `shape.ruleStyle` is `double`) rule under it. Panels use `--brand-radius-lg` and `--brand-shadow-hero`; skeletons inside the hero tint from the hero ink. A brand therefore supplies one hero, legible in both modes, not a pair.

Components read only the derived properties, emitted by `homeDeclarations` in `theme/brands/css.ts` (brands.css snapshot `tests/unit/brand/brands.css.snapshot`); `docs/architecture/brands.md` lists them. Constraints a design must respect: the hero title is the one element whose size is computed from its container and its text (`data-tier`); the `primary` tile must keep its inverted label at 4.5:1 in both modes, including pressed (festival, 80 % mix, 4.76; guarded by `brandContract.test.ts`); "See all" and the season meta row must survive a 222 px aside.

#### Keyboard and focus order

Skip link, wordmark, (drawer button | nothing), theme toggle, invite bell and account menu (member) or Create account and Log in (logged out), nav links, then `main`: **links inside the updates markdown** (left column, first), then the New league button, then each season card (a single link per card), then footer links. The hero and updates card are not focusable. Season cards have a 4 px-offset focus ring and a hover tint. The disabled New league button while the session loads (Mantine `data-disabled` on an anchor): whether it stays in the tab order is **Unverified**.

#### Real-time and refresh

The orchestration loads once per mount (and when the user flips between logged in and out); there is no polling or socket on Home, so a draft that starts while the page is open does not change its chip until reload. Content states keep prior `ready` data on refresh (`prev.state === "ready" ? prev : ...`).

### 6.2 Focus order and landmarks

- Every layout starts with a skip link to `#main-content`. The draft layout has no site header or nav; the draft header (`DraftBoardHeader`) is rendered in `DraftRoomScreen` before `<main id="main-content" class="dr-body">`, i.e. outside the main landmark, with the skip link first.
- Draft DOM order on desktop: header, runtime banners, ledger rail, board, my roster rail, auto-draft rail (`DraftRoomScaffold.tsx`). On mobile: header, categories, bottom `nav` (`aria-label="Draft rails"`), footer.
- Shell DOM order: skip link, header, drawer, session error, nav, banners, main, footer.

### 6.3 Live regions

- `DraftLiveRegion` announces the latest confirmed pick and whose turn it is; optimistic rows are not announced until confirmed. `PageLoader` is `role=status`; `PageError` is `role=alert`. The connection indicator's role is **Unverified**.
- Countdown beeps are audio only and the visual cue is a colour pulse: there is **no text or icon equivalent** for urgency.

### 6.4 Touch targets

- Board pills are about 22 px tall (`pillH` 22 in `decisions/draftRoomLayout.ts`), well under 44 px; mobile pills are taller but still about 24-28 px in the screenshot. Icon buttons use small `ActionIcon` sizes (`FO_ICON_SIZE_SM_PX` 22). A redesign should state target sizes explicitly rather than inherit these.

### 6.5 Drag and drop

- `@dnd-kit` sortable rows in admin categories, admin nominations and personal draft plans, with a left grip handle and inline drag styles from `shared/dnd/useSortableInlineStyle.ts`. Keyboard reordering support is **Unverified** (sensors not read).

### 6.6 Optimistic and real-time updates

- One optimistic pick in flight, overlaid on the snapshot and rolled back on error (`orchestration/draft/useDraftRoomActions.ts`).
- Socket events and heartbeats change the snapshot at any moment. The board can lose an armed nominee (someone else drafted it) while the user is mid-keystroke: the effect clearing selection whenever `canDraftAction` turns false disarms the pill and cancels the confirm toast with no explanation.
- Turn flips change interactivity and styling in one frame; the chime fires only on false-to-true.
- Clock skew is corrected (`decisions/draft/clockSkew.ts`). The buckle text changes every second, so its width must not jump.
- Cursor ghosts move at animation-frame rate over the board; whether they pass pointer events through is **Unverified**.
- Banners arriving mid-session push shell content down; in the draft room `RuntimeBannerStack` sits between header and body and shifts the body.

## 8. Complexity hot spots (ranked)

1. **Draft room header and buckle.** One element carries about ten states (not started, paused, active name, clock, countdown pulse, mine/theirs recolour, rolling tied winners, three podium buckles, preview) and measures itself against a variable-length participant strip. A mockup with "avery" and "Round 3" oversimplifies it. Design for 61-char and 2-char usernames, 2-12 seats, a clock string like "120s • 119s left" that changes every second without resizing, text and a red pulse on a gold buckle in both modes and every brand, and the same bar as a full-width strip at 390.
2. **Nominee pills and the board.** Long labels are the norm and clip to one line. The same pill must express armed, muted (drafted), pending (dashed), winner, hover-match (another seat's picks), focus-visible on an `aria-disabled` element, and mine-versus-theirs hover, at 22-28 px height and still legible at 50 % opacity. Armed is ink (with a check), hover-match is an ink tint and winner is win gold, so the three must stay distinguishable in every brand (win gold must not be mistaken for a brand primary such as ballot or festival's). Wrapped category titles break the masonry height estimate.
3. **Three-rail layout, compact rails and the mobile tree.** Rails open and collapse by unit maths, are remembered per user, go mutually exclusive below 665 px, and are replaced by a bottom bar and panes on phones. The 500-900 range uses the desktop tree with a squeezed header and is untested, so every mock must say what happens at 768.
4. **Final results and ties.** Podium buckles, a winner label rolling through tied names, roster cards with running scores and gold winning picks, in two layouts. Needs ties for first and for second, long names, a zero-score row, and a result that changes while watching.
5. **Optimistic and real-time transitions.** Pending dashed rows, rolled-back picks with a toast, an armed pill vanishing because someone else drafted it, turn flips, a reconnecting state that disables picks; the confirm toast is lifted above the phone rail bar, so its height counts against the viewport. Most are momentary and must not shift layout.
6. **Gold versus primary.** Split in code (#397): `--brand-primary` (buttons, active underline, wordmark, checkboxes, live buckle) is separate from `--fo-win-gold*` (winner pills, final-results buckle, podium first). The remaining risk is visual: refined-gold's primary is gold-hued, and brands with a green, red or cherry primary (festival, technicolor) put a status-like hue on buttons and the live buckle next to win gold. Check every brand for confusion between primary, win gold and the status colours.
7. **Admin console on small screens.** Overflow at 390 is fixed (#397: nav wraps, wizard stacks, nominee rows wrap) but the workflow stepper, nested sub-nav, sortable lists with drag handles, TMDB link states and merge modals are dense and still have no designed responsive layout. `account` and `draft-plans` still overflow at 390 (`KNOWN_PHONE_OVERFLOW`).
8. **Season dashboard variants.** The page changes by role (member or commissioner), draft status (pre-draft through archived), ceremony status (locked, complete) and has disabled-with-reason buttons. Status chips now carry tone and a mark (#404), so every list that shows lifecycle (season, seasons index, league detail, landing) must keep the colour on the border and mark only, the label in ink, and a neutral chip for pre-draft and closed.
9. **Two CSS generations and doubled dark selectors.** `baseline-*` and `.card`/`.fo-legacy` coexist; many rules are written twice (`:root[...]` and `body[...]`) and override Mantine variables with `!important`. Change cost is higher than the component count suggests, so migrate by family.
10. **Motion, audio and colour-only cues.** Countdown pulse and beeps, turn chime, rolling names, cursor ghosts. Reduced motion is handled globally (durations clamped to 0.01 ms) and the countdown holds its red phase. The countdown now has non-colour cues (timer glyph, "{N}s left" words, inner ring), alerts have severity glyphs and status chips have marks; remaining colour-only signals are hover-match tint versus muted pills and the toast severities (no glyph).
