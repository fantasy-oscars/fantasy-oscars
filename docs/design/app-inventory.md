# App inventory

A map of the web app for people who prescribe and judge visual changes. It was written from the code at `origin/main` after PR #394, corrected after PRs #395-#400 (structural prerequisites, brand token contracts and palettes) and updated after PRs #403 (brand header, nav, wordmark, buttons) and #404 (brand cards, decorations, chips, alerts, countdown cue, `EmptyState`) the picker-and-launch package (Appearance settings, per-person daily draw, wordmark shuffle, mode toggles removed, phone 44 px targets) and the visual baselines in `tests/visual/__screenshots__`. Paths are relative to `apps/web/src` unless they start with `tests/`, `docs/` or `packages/`.

"Today" means the released themes: those in `ENABLED_BRAND_IDS` (`packages/shared/src/brands.ts`); the launch step enables all seven. Defined brands: refined-gold (`theme/brands/refined-gold.ts`, also `STARTING_BRAND`), red-carpet, noir, ballot, festival, technicolor and lightbox (all in `BRAND_IDS`, `BRAND_DEFINITIONS` and `BRAND_CATALOG`, which also gives each its collection, Ceremony or Cinema, and its modes). The visual suite and tests can show any defined brand regardless of release. Where something could not be confirmed from code or screenshots it is marked **Unverified**.

Glue: `app/pages/HomePage.tsx` calls `useLandingOrchestration({ seasonsEnabled: Boolean(user) })` (`orchestration/landing/orchestration.ts`) and renders `features/home/screens/LandingScreen.tsx` inside `ShellLayout` (header, nav, banners, footer; the shell constrains width and applies gutters). `LandingLayout` (`primitives/layouts/LandingLayout.tsx`) is a three-region grid (`hero`, `updates`, `aside`); the screen builds each as a node. #### Keyboard and focus order

Skip link, wordmark, (drawer button | nothing), invite bell and account menu (member) or Create account and Log in (logged out), nav links, then `main`: **links inside the updates markdown** (left column, first), then the New league button (in red carpet it comes before the updates, inside the hero), then each season card (a single link per card), then footer links. The disabled New league button while the session loads (Mantine `data-disabled` on an anchor): whether it stays in the tab order is **Unverified**.

#### Real-time and refresh

The orchestration loads once per mount (and when the user flips between logged in and out); there is no polling or socket on Home, so a draft that starts while the page is open does not change its chip until reload. Content states keep prior `ready` data on refresh (`prev.state === "ready" ? prev : ...`).

### 6.2 Focus order and landmarks

- Every layout starts with a skip link to `#main-content`. The draft layout has no site header or nav; the draft header (`DraftBoardHeader`) is rendered in `DraftRoomScreen` before `<main id="main-content" class="dr-body">`, i.e. outside the main landmark, with the skip link first.
- Draft DOM order on desktop: header, runtime banners, ledger rail, board, my roster rail, auto-draft rail (`DraftRoomScaffold.tsx`). On mobile: header, categories, bottom `nav` (`aria-label="Draft rails"`), footer. The header tab is a labelled group (not a focus stop); the roster track follows the board, with its previous and next buttons before the cards and arrow keys stepping the window; collapsing or expanding a rail returns focus to that rail's toggle.
- Shell DOM order: skip link, header, drawer, session error, nav, banners, main, footer.

### 6.3 Live regions

- `DraftLiveRegion` announces the latest confirmed pick and whose turn it is; optimistic rows are not announced until confirmed; it also says "Reconnected" after a drop. The roster track has its own polite live region for the visible seats. `PageLoader` is `role=status`; `PageError` is `role=alert`. The connection indicator's role is **Unverified**.
- Countdown beeps are audio only and the visual cue is a colour pulse: there is **no text or icon equivalent** for urgency.

### 6.4 Touch targets

- Board pills are about 22 px tall (`pillH` 22 in `decisions/draftRoomLayout.ts`), well under 44 px; mobile pills are taller but still about 24-28 px in the screenshot. Icon buttons use small `ActionIcon` sizes (`FO_ICON_SIZE_SM_PX` 22). A redesign should state target sizes explicitly rather than inherit these.
- Phone (below 500) 44 px families, now enforced by the assertion tier (`--fo-touch-target`): footer links and logo, text inputs and Select/MultiSelect (`--input-height-sm`, set on `.page`, `.auth-page`, `.dr-frame`, `.mantine-Modal-root` wrappers), wordmark link, admin `nav-link` (also 44 wide) and nominee group headers, draft rail buttons (44, bottom bar 56), menu items (`--fo-menu-item-height`), modal buttons, Modal and Notification close buttons, Appearance segments and options.
- Stay allowlisted (`tests/visual/assertions/allowlist.ts`, seven entries): `Checkbox-input` (label is the target), `nomination-drag-handle-button` (18 px, admin only; keyboard reorder now exists, the handle size is unchanged), `mantine-Stepper-step` (32 px, admin), `dr-pill` (22 px, meets WCAG 2.5.8 by spacing; a tap opens the sheet whose Draft button is 44), `dr-card-titleRow` (20 px, keyboard entry to pill mode), `mantine-NumberInput-control` (specimen only).

### 6.5 Drag and drop

- `@dnd-kit` sortable rows in admin categories, admin nominations and personal draft plans, with a left grip handle and inline drag styles from `shared/dnd/useSortableInlineStyle.ts`. Admin categories and nominees use `shared/dnd/useReorderSensors.ts` (PointerSensor, distance 4 on nominees, plus KeyboardSensor with `sortableKeyboardCoordinates`): focus the grip, Space lifts, Arrow keys move, Space drops, and the same `onDragEnd` runs as for a mouse drag. `DraftPlansScreen` still configures PointerSensor only (no keyboard reorder). The grip stays 18 px (allowlisted).

### 6.6 Optimistic and real-time updates

- One optimistic pick in flight, overlaid on the snapshot and rolled back on error (`orchestration/draft/useDraftRoomActions.ts`).
- Socket events and heartbeats change the snapshot at any moment. The board can lose an armed nominee (someone else drafted it) while the user is mid-keystroke: the effect clearing selection whenever `canDraftAction` turns false disarms the pill and cancels the confirm toast with no explanation.
- Turn flips change interactivity and styling in one frame; the chime fires only on false-to-true.
- Clock skew is corrected (`decisions/draft/clockSkew.ts`). The tab clock changes every second and uses tabular digits, so its width must not jump.
- Cursor ghosts move at animation-frame rate over the board; whether they pass pointer events through is **Unverified**.
- Banners arriving mid-session push shell content down; in the draft room `RuntimeBannerStack` sits between header and body and shifts the body.

## 8. Complexity hot spots (ranked)

1. **Draft room header tab.** One element carries about ten states (not started, paused, active name, clock, countdown pulse, mine/theirs recolour, rolling tied winners, three podium places, preview) and measures itself against a variable-length participant strip. A mockup with "avery" and "Round 3" oversimplifies it. Design for 61-char and 2-char usernames, 2-12 seats, a clock string like "120s • 119s left" that changes every second without resizing, text and a red pulse on a gold tab in both modes and every brand, and the same tab at 390 between 44 px buttons, and the compaction hysteresis (the header collapses its wings by path, so a near-threshold width gives different results).
2. **Nominee pills and the board.** Long labels are the norm and clip to one line. The same pill must express armed, muted (drafted), pending (dashed), winner, hover-match (another seat's picks), focus-visible on an `aria-disabled` element, and mine-versus-theirs hover, at 22-28 px height and legible when drafted (muted ink on a sunken fill, 5.1 to 7.5:1 across the 14 palettes). Armed is ink (with a check), hover-match is an ink tint and winner is win gold, so the three must stay distinguishable in every brand (win gold must not be mistaken for a brand primary such as ballot or festival's). Wrapped category titles break the masonry height estimate.
3. **Three-rail layout, compact rails and the mobile tree.** Rails open and collapse by unit maths, are remembered per user, go mutually exclusive below 665 px, and are replaced by a bottom bar and panes on phones. The 500-900 range uses the desktop tree with a squeezed header and is untested, so every mock must say what happens at 768.
4. **Final results and ties.** A podium of up to three places in the header tab, a place rolling through tied names, a rotating roster window, roster cards with running scores and gold winning picks, in two layouts. Needs ties for first and for second, long names, a zero-score row, and a result that changes while watching.
5. **Optimistic and real-time transitions.** Pending dashed rows, rolled-back picks with a toast, an armed pill vanishing because someone else drafted it, turn flips, a reconnecting state that disables picks; the confirm toast is lifted above the phone rail bar, so its height counts against the viewport. Most are momentary and must not shift layout.
6. **Gold versus primary.** Split in code (#397): `--brand-primary` (buttons, active underline, wordmark, checkboxes, live tab) is separate from `--fo-win-gold*` (winner pills, final-results tab, podium first). The remaining risk is visual: refined-gold's primary is gold-hued, and brands with a green, red or cherry primary (festival, technicolor) put a status-like hue on buttons and the live tab next to win gold. Check every brand for confusion between primary, win gold and the status colours.
7. **Admin console on small screens.** Overflow at 390 is fixed (#397: nav wraps, wizard stacks, nominee rows wrap) but the workflow stepper, nested sub-nav, sortable lists with drag handles, TMDB link states and merge modals are dense and still have no designed responsive layout. `KNOWN_PHONE_OVERFLOW` is now empty, so no screen is excused from phone overflow.
8. **Season dashboard variants.** The page changes by role (member or commissioner), draft status (pre-draft through archived), ceremony status (locked, complete) and has disabled-with-reason buttons. Status chips now carry tone and a mark (#404), so every list that shows lifecycle (season, seasons index, league detail, landing) must keep the colour on the border and mark only, the label in ink, and a neutral chip for pre-draft and closed.
9. **Two CSS generations and doubled dark selectors.** `baseline-*` and `.card`/`.fo-legacy` coexist; many rules are written twice (`:root[...]` and `body[...]`) and override Mantine variables with `!important`. Change cost is higher than the component count suggests, so migrate by family.
10. **Appearance section and the daily theme.** The first place a person controls the brand: a card with up to four controls whose set changes by state (floor, discovery, one-mode themes, unreleased Fixed theme, save failure), a list that opens over the page and scrolls on a phone, and a theme that changes at login or by a hidden click. Design every state in section 3.3 at 390 (vertical segments, 44 px rows), keep the status line's reserved height, and expect the page to repaint (all tokens, fonts) when Mode or Fixed changes.
11. **Motion, audio and colour-only cues.** Countdown pulse and beeps, turn chime, rolling names, cursor ghosts. Reduced motion is handled globally (durations clamped to 0.01 ms) and the countdown holds its red phase. The countdown now has non-colour cues (timer glyph, "{N}s left" words, inner ring), alerts have severity glyphs and status chips have marks; remaining colour-only signals are hover-match tint versus muted pills and the toast severities (no glyph).
