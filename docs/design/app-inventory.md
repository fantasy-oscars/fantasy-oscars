# App inventory

A map of the web app for people who prescribe and judge visual changes. It was written from the code at `origin/main` (after the brand-token contract and self-hosted brand fonts landed) and the visual baselines in `tests/visual/__screenshots__`. Paths are relative to `apps/web/src` unless they start with `tests/`, `docs/` or `packages/`.

"Today" means the single shipped brand, `refined-gold` (`theme/brands/refined-gold.ts`). Where something could not be confirmed from code or screenshots it is marked **Unverified**.

## 3. State inventory per screen

Common building blocks (`shared/page-state.tsx`): `PageLoader` (`role=status`, `aria-live=polite`, "Checking session…" or custom label) and `PageError` (`role=alert`, red Alert with optional request id). Each screen has its own skeleton of `Skeleton` blocks with fixed-percentage widths. ### 6.2 Focus order and landmarks

- Every layout starts with a skip link to `#main-content`. The draft layout has no header or nav landmark; the header sits inside `main`.
- Draft DOM order on desktop: header, runtime banners, ledger rail, board, my roster rail, auto-draft rail (`DraftRoomScaffold.tsx`). On mobile: header, categories, bottom `nav` (`aria-label="Draft rails"`), footer.
- Shell DOM order: skip link, header, drawer, session error, nav, banners, main, footer.

### 6.3 Live regions

- `DraftLiveRegion` announces the latest confirmed pick and whose turn it is; optimistic rows are not announced until confirmed. `PageLoader` is `role=status`; `PageError` is `role=alert`. The connection indicator's role is **Unverified**.
- Countdown beeps are audio only and the visual cue is a colour pulse: there is **no text or icon equivalent** for urgency.

### 6.4 Touch targets

- Board pills are about 22 px tall (`pillH` 22 in `decisions/draftRoomLayout.ts`), well under 44 px; mobile pills are taller but still about 24-28 px in the screenshot. Icon buttons use small `ActionIcon` sizes (`FO_ICON_SIZE_SM_PX` 22). A redesign should state target sizes explicitly rather than inherit these.

### 6.5 Drag and drop

- `@dnd-kit` sortable rows in admin categories, admin nominations and personal draft plans, with a left grip handle and inline drag styles from `shared/dnd/useSortableInlineStyle.ts`. Keyboard reordering support is **Unverified** (sensors not read).

### 6.6 Optimistic and real-time updates

- One optimistic pick in flight, overlaid on the snapshot and rolled back on error (`orchestration/draft/useDraftRoomActions.ts`).
- Socket events and heartbeats change the snapshot at any moment. The board can lose an armed nominee (someone else drafted it) while the user is mid-keystroke: the effect clearing selection whenever `canDraftAction` turns false disarms the pill and cancels the confirm toast with no explanation.
- Turn flips change interactivity and styling in one frame; the chime fires only on false-to-true.
- Clock skew is corrected (`decisions/draft/clockSkew.ts`). The buckle text changes every second, so its width must not jump.
- Cursor ghosts move at animation-frame rate over the board; whether they pass pointer events through is **Unverified**.
- Banners arriving mid-session push shell content down; in the draft room `RuntimeBannerStack` sits between header and body and shifts the body.

## 8. Complexity hot spots (ranked)

1. **Draft room header and buckle.** One element carries about ten states (not started, paused, active name, clock, countdown pulse, mine/theirs recolour, rolling tied winners, three podium buckles, preview) and measures itself against a variable-length participant strip. A mockup with "avery" and "Round 3" oversimplifies it. Design for 61-char and 2-char usernames, 2-12 seats, a clock string like "120s • 119s left" that changes every second without resizing, text and a red pulse on a gold buckle in both modes and every brand, and the same bar as a full-width strip at 390.
2. **Nominee pills and the board.** Long labels are the norm and clip to one line. The same pill must express armed, muted (drafted), pending (dashed), winner, hover-match (another seat's picks), focus-visible on an `aria-disabled` element, and mine-versus-theirs hover, at 22-28 px height and still legible at 50 % opacity. Gold is the hover, armed and winner colour at once. Wrapped category titles break the masonry height estimate.
3. **Three-rail layout, compact rails and the mobile tree.** Rails open and collapse by unit maths, are remembered per user, go mutually exclusive below 665 px, and are replaced by a bottom bar and panes on phones. The 500-900 range uses the desktop tree with a squeezed header and is untested, so every mock must say what happens at 768.
4. **Final results and ties.** Podium buckles, a winner label rolling through tied names, roster cards with running scores and gold winning picks, in two layouts. Needs ties for first and for second, long names, a zero-score row, and a result that changes while watching.
5. **Optimistic and real-time transitions.** Pending dashed rows, rolled-back picks with a toast, an armed pill vanishing because someone else drafted it, turn flips, a reconnecting state that disables picks, the confirm toast stacking over the mobile bottom bar. Most are momentary and must not shift layout.
6. **Gold overload.** Gold is brand primary (buttons, active underline, wordmark, checkboxes, focus ring), win gold, the draft buckle, hover and winner. The contract separates `primary` from the shared win gold; the code does not. Giving a brand a non-gold primary will expose every place that still reads `--fo-gold-primary` as "primary".
7. **Admin console on small screens.** The phone screenshot shows a clipped top nav and form cards wider than the viewport. The workflow stepper, nested sub-nav, sortable lists with drag handles, TMDB link states and merge modals are dense and have no responsive design.
8. **Season dashboard variants.** The page changes by role (member or commissioner), draft status (pre-draft through archived), ceremony status (locked, complete) and has disabled-with-reason buttons. Status chips are grey today; adding status colours touches every list that shows lifecycle (season, seasons index, league detail).
9. **Two CSS generations and doubled dark selectors.** `baseline-*` and `.card`/`.fo-legacy` coexist; many rules are written twice (`:root[...]` and `body[...]`) and override Mantine variables with `!important`. Change cost is higher than the component count suggests, so migrate by family.
10. **Motion, audio and colour-only cues.** Countdown pulse and beeps, turn chime, rolling names, cursor ghosts. No reduced-motion path and no non-colour urgency cue.
